# SAJA: بوابات مراجعة المحتوى الشرعي وإشعارات العبادات

**حالة هذا الملف: خطة مراجعة داخلية وليست اعتمادًا شرعيًا.**

## واقع النشر الحالي
- `src/content/knowledge.ts` معلّم صراحة كمواد تجريبية غير معتمدة.
- `src/content/hadith.ts` مجموعة محدودة معلّمة `demo-unreviewed`، والنصوص العربية وروابطها بحاجة إلى مراجعة بشرية لكل نسخة مطابقة.
- محتوى القصص الخيالية وأنشطة الحديث ليس حديثًا نبويًا ولا واقعة تاريخية ويجب تمييزه دائمًا.
- قاعدة البيانات لديها سير عمل `draft → internal_review → scholar_review → approved → published`، وحالة المنشور تُقرأ من `/api/content/status` بحساب مخوّل، ولا تُستنتج من حالة الكود فقط.
- `scripts/content-review-queue.ts` ينتج قائمة النصوص التي تحتاج فحصًا متخصصًا؛ ليس حكمًا على صحتها.

## تدقيق إضافات «يومي»
- «أذكار الصباح والمساء» تشير للعبادة والوقت فقط؛ لم نُدخل أحاديث مجهولة المصدر أو أعداد فضائل غير متحققة.
- يظهر مبدأ الصدقة دون مَنّ أو أذى مع الإحالة إلى البقرة 2:264؛ النص التفسيري لا يحمل وسم `reviewed` قبل مراجعة متخصص.
- لا توجد حسابات «ثواب» أو «ذنب» أو سلاسل تسجيل إجبارية أو رسائل تأنيب، ولا تُنشر حالة أداء العبادات للمجتمع.
- أذكار الصباح والمساء بإشعارات متكررة **مغلقة افتراضيًا** ولا تُفعّل إلا باختيار المستخدم؛ Push يتطلب اشتراك جهاز وحسابًا متصلًا ومفاتيح VAPID. وضع الطفل يمنع Push على الخادم.
- الإشعارات تستند إلى المنطقة الزمنية التي اختارها المستخدم، لا إلى موقع GPS، وتفوت نافذة الإرسال لو الخادم متوقف بدل إرسال تنبيه متأخر لساعات.
- الصوت لا يعمل تلقائيًا؛ التسجيلات المختارة من Wikimedia Commons مع نسب المؤلف والترخيص، ويجب إعادة تدقيق حقوقها وتوافق المتصفح قبل الإطلاق.
- وقت الصلاة حساب فلكي يتأثر بالمدينة والمذهب وطريقة الحساب؛ يراجع المستخدم توقيت الجهة المحلية المعتمدة.

## اعتماد بشري مطلوب قبل إطلاق النصوص
1. تعيين مراجع مؤهل للفقه والقرآن والحديث والتفسير مع فصل دور المراجع عن صلاحية النشر.
2. مقارنة نص كل آية وكل متن ومصدر ودرجة حديث وترجمة ومعنى والسياق مع المصدر الأصلي؛ التوثيق يشمل رقم النسخة وبصمتها.
3. فحص كل جملة تتحدث عن فضل مخصوص أو ثواب أو إبطال عبادة من متخصص، مع ذكر اختلافات المذاهب حيث يلزم.
4. مطالعة لقطات الواجهة للأطفال، ومراجعة التبليغ وولي الأمر وضوابط الحسابات، لا الاكتفاء باختبار ترشيح بطاقات الفهرس.
5. منع نشر المحتوى الجديد قبل `published_version` في سجل المحتوى، أو وضع وسم تجريبي واضح.

## تدقيق الأداء والاعتماديات
- للقرية وضع قياس محلي `?perf=1` يعرض FPS وDPR وDraw Calls وTriangles. يُجرَّب على Mac وAndroid وiOS مع المقارنة بوضع 2D وحالة البطارية.
- يجري إنشاء مرشح GLB بخطوات `dedup` و`prune` دون ضغط فاقد، مع التحقق من البنية وقنوات الحركة. لا يُستبدل الأصل قبل اختبار حركة الشخصية والاصطدامات بصريًا.
- `npm audit` يُصدر تقريرًا بالاعتماديات إلى Artifact؛ لا تُشغّل `npm audit fix --force` بشكل تلقائي.
