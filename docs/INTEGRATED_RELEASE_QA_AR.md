# SAJA — تقرير مراجعة التكامل قبل الإطلاق
آخر مراجعة: 9 نوفمبر 2026 · الفرع: `integration/experience-hub-v1-living-village-v2`

## نطاق التنفيذ
- تخصيص الصفحة الأولى بحسب اختيار المستخدم ومرحلة العمر، دون استنتاج معتقده أو تغيير موافقات ولي الأمر.
- فهرس للمحتوى المحلي مع بحث وتصنيفات، مع الاحتفاظ بالمصدر الأصلي للمادة.
- إظهار حالة المحتوى على كل بطاقة: رابط لقسم / مادة تجريبية / حكاية خيالية / مراجعة في النسخة المجمعة. لا تعني الإشارة المحلية أن المادة منشورة أو معتمدة شرعياً على الخادم.
- تحسينات شاشة الموبايل: مساحات ضغط لا تقل عن 48px للعناصر المعنية، خطوط مرنة، اتجاه عربي RTL، معالجة ضيق شاشات 320-390px.
- رسومات القرية: 16 فانوسًا عبر ثلاثة `InstancedMesh` بدل 48 `Mesh` منفصلًا. ضبط دقة الرسم تدريجيًا وفق معدل الإطارات من دون تعديل فيزياء الحركة؛ طلب GLB يبدأ بالتوازي مع تحميل واجهة العالم عند دخوله؛ عزل مكتبات محرّك الرسم في Chunk مؤجّل قابل للتخزين المؤقت.

## نتائج مثبتة ومحدودية القياس
- اختبار GitHub `npm run check` يشمل TypeScript وESLint وVitest وبناء الإنتاج. يُراجع آخر تشغيل من صفحة PR #6، ولا تُفترض النتيجة مسبقًا.
- اختبار المتصفح `npm run e2e:experience` سبق أن نجح على Mac قبل تحسينات الأداء والواجهة الحالية؛ ينبغي إعادة تشغيله على النسخة الجديدة.
- `npm run e2e:audiences` يتحقق من 4 مسارات للبالغين (الاهتمام/البداية/التعمق بالإنجليزية والتعمق بالعربية) ومسار طفل بالعربية، ويُنتج لقطات على مقاس الموبايل للمراجعة اليدوية.
- فصل `village-renderer` يقلّل حجم ملف `Village3D` منفردًا ويساعد التخزين المؤقت، **لكنه لا يعني تخفيض مجموع البايتات المطلوبة على أول دخول للعالم**. تقليل عدد Draw Calls وضبط DPR يهدفان لتحسين الأداء دون نسبة FPS مضمونة.
- ملف `public/assets/game/saja-village.glb` الحالي يقارب 3.4 MB؛ لم يُضغط أو تُعدّل خاماته في هذا التغيير، حتى لا نفقد التحريك أو جودة النموذج. قياس WebGL سابق في Headless Chrome كان نحو 7 FPS وغير ممثل للأجهزة الحقيقية.

## مراجعة الأمان والمحتوى
- فهرس الطفل يُرشح بحسب `ageBand`؛ أي تعديل لهدف التعلم أو عمق الشرح لا يفتح عناصر `teen/adult`. هذا **ترشيح واجهة فقط** وليس تحكم صلاحيات.
- حماية الرسائل والحلقات والمراجعة الشرعية الأساسية موجودة في الخادم وتغطيها اختبارات أمن مستقلة. يجب تجربة روابط الوصول المباشر، والحسابات، وموافقة ولي الأمر مع بيانات فعلية في بيئة مغلقة.
- أسئلة «اسأل متخصصًا» تمر عبر تنظيف للمعطيات ومراجعة/حجز المحتوى المثير للمخاطر؛ يجب التأكد من أن أي معلومات تعريفية للقُصّر لا تُنشر في أية مرحلة.
- قصص القرية **خيالية تعليمية وليست آيات أو أحاديث أو سيرة موثقة**؛ مراجعة النصوص الدينية تظل إجراءً مستقلًا من صاحب الاختصاص قبل النشر.
- فهرس V1 يعرض مصادر مجمعة مع حقل حالة محلي، ولا يجلب تلقائيًا كل حالات النشر الحية من API. **لا يجب وسم مادة بأنها منشورة اعتمادًا على الفهرس وحده**.

## بوابات إلزامية قبل النشر العام
1. نجاح CI الحالي، بما فيه اختبارات واجهات الموبايل؛ مراجعة لقطات Arabic/English بصريًا، وليس مجرد فحص وجود العناصر.
2. اختبار القرية الحقيقي على Mac وAndroid وiPhone/متصفح Safari: التحريك، التصادم، التحكم باللمس، FPS ووقت تحميل العالم على اتصال بطيء.
3. مراجعة جميع حالات محتوى القرآن والحديث والتفسير والمصادر من طرف مؤهل؛ التأكد من تطابق حالة المراجعة مع سجل الخادم.
4. مراجعة الحماية من الوصول المباشر، والرسائل، والحلقات، ومدد الاستخدام وإذن ولي الأمر.
5. مراجعة مخرجات `npm audit` بالتفصيل (كانت هناك 10 تحذيرات متوسطة في تشغيل محلي سابق)، وتطبيق تحديثات آمنة مع إعادة الاختبار دون `--force` افتراضيًا.
6. بقاء PR #6 في حالة Draft، وعدم دمج التغييرات أو نشرها قبل اكتمال هذه البوابات.

## أوامر QA على جهاز Mac
```bash
cd "$HOME/Desktop/كل المشاريع/SAJA/النسخة الحالية/مصادر العمل المحلية/saja-integrated-review" || exit 1
git status --short
git fetch origin
git switch --detach origin/integration/experience-hub-v1-living-village-v2
npm run check
npm run e2e:game
npm run e2e:experience
npm run e2e:audiences
npm run dev:review
```
لا تُعدّل الملفات المحلية غير المتعلقة بالمشروع (مثل الصور الملتقطة) دون مراجعتها؛ `git switch` يرفض الكتابة فوق التغييرات المتعارضة.
